# M3 CPU smoke — 2026-09-10

## Назначение

Проверить связность реализованного конвейера BC → PPO → evaluation → ONNX до
канонического запуска в WSL2/CUDA. Это инженерный smoke, а не измерение качества
обученной политики: использованы две validation-задачи и по одному шагу BC/PPO.

## Зафиксированная среда

- Windows, Python 3.13.14;
- PyTorch 2.14.0+cpu, float32, deterministic algorithms;
- dataset manifest
  `7aa6ad9ef4e100da855194b30ea1baa0bd4dd8467e45049e296f254ab6ee1cc6`;
- canonical training config SHA-256
  `d917b6a24496db5038c4e1cfe899cd9e3ce1bd7deb422d592ee132555a0f22d4`.

## Результат

- команды `train --smoke`, `evaluate --smoke`, `export-onnx` и
  `verify-model` завершились успешно;
- два независимых smoke-запуска дали одинаковые SHA-256 BC checkpoint, PPO
  checkpoint и `metrics.jsonl`;
- оба ONNX-графа имеют opset 23;
- ONNX Runtime повторил 2353 greedy-действия PyTorch на всех 128 validation
  задачах с допуском logits `1e-5`;
- smoke hybrid дал 2 из 2 полных независимо валидных решений и ни одного
  проигрыша замороженному `random-left-bottom/64`;
- строгих улучшений в smoke-подмножестве нет, поэтому `qualityGatePassed=false`.

Этот результат подтверждает инфраструктуру, но не закрывает M3. Исследовательский
вывод можно делать только после полного CUDA-обучения, выбора checkpoint по
validation и однократной оценки на 128 test-задачах.
