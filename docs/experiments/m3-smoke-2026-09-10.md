# M3 CPU пробный — 2026-09-10

## Назначение

Проверить связность реализованного конвейера BC → PPO → оценка → ONNX до
канонического запуска в WSL2/CUDA. Это инженерный пробный, а не измерение качества
обученной политики: использованы две проверочные задачи и по одному шагу BC/PPO.

## Зафиксированная среда

- Windows, Python 3.13.14;
- PyTorch 2.14.0+cpu, `float32`, детерминированный алгоритмы;
- набор данных манифест
  `7aa6ad9ef4e100da855194b30ea1baa0bd4dd8467e45049e296f254ab6ee1cc6`;
- канонический обучение конфигурация SHA-256
  `d917b6a24496db5038c4e1cfe899cd9e3ce1bd7deb422d592ee132555a0f22d4`.

## Результат

- команды `train --smoke`, `evaluate --smoke`, `export-onnx` и
  `verify-model` завершились успешно;
- два независимых пробных запуска дали одинаковые SHA-256 контрольных точек BC и PPO
  контрольная точка и `metrics.jsonl`;
- оба ONNX-графа имеют набор операций 23;
- механизм выполнения ONNX повторил 2353 жадных действия PyTorch на всех 128 проверочных
  задачах с допуском логиты `1e-5`;
- пробный гибридный дал 2 из 2 полных независимо валидных решений и ни одного
  проигрыша замороженному `random-left-bottom/64`;
- строгих улучшений в пробном подмножестве нет, поэтому `qualityGatePassed=false`.

Этот результат подтверждает инфраструктуру, но не закрывает M3. Исследовательский
вывод можно делать только после полного CUDA-обучения, выбора контрольная точка по
проверки и однократной оценки на 128 тестовых задачах.
