# Текущее состояние

Проверено 2026-09-17.

## базовый алгоритм

- Windows Debug приложение собирается MSVC с Qt 6.9.3.
- настольное приложение и без графического интерфейса CTest цели сборки проверяют существующее приложение и новое
  ядро решателя.
- Проект использует C++20, CMake, Qt 6 и закреплённую Git-ревизию
  `AIPackaging_Math`.
- Код разделён на контракты, домен, прикладной слой и GUI.
- Автоупаковка реализована детерминированным первое допустимое место по клеткам.
- Фигуры сериализуются списками целочисленных координат клеток.
- Независимый `AIPackaging_Solver` поддерживает пять воспроизводимых базовых алгоритмов:
  `input-first-fit`, две сортировки с размещением снизу слева, случайный поиск с
  заданным начальным значением и лучевой поиск.
- `AIPackaging_Cli` читает `grid_problem` v1 и сохраняет `grid_solution` v1 с
  независимо проверяемыми размещения, целевая функция и метриками.
- `GridLearningEnvironment` предоставляет постоянный каталог действий, маска,
  наблюдение v1, компактный траектория API и точный вознаграждение v1.
- Python-пакет `aipackaging-ml` предоставляет подобный Gymnasium API, генератор профилей
  `small`/средний и модуль проверки `grid_dataset`/`grid_trajectory` v1.
- Канонический набор данных содержит 768 задач и 3840 траекторий базовых алгоритмов; он
  генерируется локально в игнорируемом `artifacts/datasets/grid-v1`.
- Реализован конвейер M3: иерархическая политика «актор-критик», BC по
  экспертным траекториям, PPO,
  многопроцессная обработка траектория, нейросетевой/гибридный средство запуска, решение v2 и двухчастный ONNX.
- Реализован полигональный контур M4: строгий JSON, отрезки, дуги, кривые Bézier, микронные кольца,
  внешние границы и отверстия, NFP-кандидаты, пять базовых алгоритмов и повторную проверку.
- `PolygonLearningEnvironment` предоставляет динамические действия и
  растровое наблюдение 4×128×128; Python умеет создавать и проверять пробный
  набор данных.
- Проверенный пробный полигональный набор данных содержит 24 задачи и 120
  траекторий базовых алгоритмов;
  SHA-256 манифест: `da53ac408c2ec715205d11931cc0690a706ef153791aafe19fb43962b76cbc5f`.
- настольное приложение M5 содержит отдельную полигональную вкладку: строгий загрузка задачи,
  пять базовых алгоритмов, расширенные бюджеты, асинхронный ход выполнения и отмену, визуализацию
  колец и сохранение только независимо проверено результата.
- В A6 полигональный прикладной контроллер выделен в независимую цель
  `AIPackaging_Application`. Он больше не знает о Qt, JSON, файловой системе,
  `PolygonEnvironment` и конкретном поисковом API.
- `AIPackaging_DesktopInfrastructure` содержит локальный шлюз документов,
  проверяемую базовую внутреннюю реализацию и `StdThreadNestingJobRunner`.
  Поток, отмена и ограничение частоты уведомлений больше не принадлежат контроллеру.
- GUI использует только прикладные структуры данных; все точечные исключения A6
  из архитектурного списка разрешений удалены.
- В A2 общие контракты вынесены в `AIPackaging_NestingCore`, а канонический API
  получил префикс `aipackaging/nesting` без изменения форматов обмена.
- В A3 реализация разделена на `SearchContracts`, `GridCore`, `PolygonCore`,
  `Search`, `Json` и `Learning`. `SolverImpl` и `Solver` теперь являются
  `INTERFACE` совместимость цели сборки для прикладной слой/GUI до A6.
- Полигональная реализация разделена на нормализация, столкновение/зазор,
  NFP-кандидаты, целевая функция/растровый, состояние и проверка; Clipper2 и `nlohmann`/json
  локализованы в своих реализация цели сборки.
- канонический `polygon_types.h` больше не зависит от клеточного `gridtypes.h`.
- В A4 клеточные и полигональные базовые алгоритмы используют единый внутренний механизм выполнения поиска для
  порядок, жизненный цикл случайного и лучевого поиска, ограничение времени,
  отмена, ход выполнения, метрики и
  метаданные. Предметные адаптеры сохраняют прежнюю геометрию и целевая функция.
- клеточный получил управляемый `runGridProblem`; прежние полигональный ход выполнения/управление
  имена сохранены псевдонимы, а `solveGridProblem`/`solvePolygonProblem` совместимы.
- В A5 общий Python-модуль владеет канонический JSON/JSONL, детерминированный gzip,
  SHA-256, пути к частям набора данных и атомарную оболочку кэша. Клеточный и
  полигональный конвейеры обработки
  разделены на генерация, траектория, повторное проигрывание/проверка и манифест сборка.
- Старые Python импорт пути сохранены фасадами; CLI использует отдельные
  набор данных/ML обработчики, поэтому генерация/проверка не импортируют PyTorch.
- В `M6.1R` поверх границ A5 добавлены рабочий полигональный набор данных v2, профили,
  парные масштабные варианты семейств, нативную проверку скрытой раскладки,
  возобновление и замороженное
  сравнительное испытание базовых алгоритмов. Набор данных v1 остаётся читаемым.

## Инфраструктура проверки

- Обычные предустановки используют `BUILD_TESTS=OFF`; для тестов нужен тест предустановка.
- конфигурация настольного приложения требует локальный `Qt6_DIR` или `CMAKE_PREFIX_PATH`;
  `windows-headless-tests` собирает решатель и CLI без Qt.
- `testCountour2D.cpp` включён в цель сборки тестов и проверяет публичные `Create` и
  `GetPoints`.
- MSVC собирает C++ с `/EHsc`; предупреждение `C4530` устранено.

  Python 3.13; Qt настольное приложение пока проверяется локально.
- `tools/run_checks.py` предоставляет единые команды `architecture`, `nesting`, `headless`,

## Ограничения геометрии настольного приложения

- Фигура — набор квадратных `Cell2D`, а не полигон с кольцами.
- Повороты на четверть оборота выполняются вокруг целочисленной опорной клетки.
- Пересечения определяются через ограничивающие прямоугольники фигур и клеток.
- Контур клетки дискретизирует кривые фиксированным числом точек и не является
  границей целой детали.
- Клеточная GUI-модель не использует полигональные ограничения; отдельная
  полигональная вкладка показывает результат решателя без ручного редактирования.
- Загрузка сцены принимает только `cell_grid` и сериализованный поворот 0°.

## Ограничения ML

M6.2 предоставляет полигональное наблюдение v2, иерархическую модель PyTorch,
вознаграждение по целевой функции, возобновляемые BC/PPO и проверяемые режимы
`greedy`, `best-of` и `hybrid`. Канонический восьмичасовой эксперимент на
Windows CUDA завершён и зафиксирован без изменения весов. На 64 тестовых
задачах гибрид получил 14 побед, 50 равенств и ни одного поражения относительно
`random-left-bottom/64`; `usedLength` улучшен в восьми задачах. Критерий M6.2
пройден. Полигональная модель пока не подключена к GUI и не экспортирована в
ONNX.

Подробности и хеши приведены в
[отчёте M6.2](experiments/m6-2-polygon-policy-2026-09-16.md).

Код обучения, манифест локального запуска и ONNX-экспорт добавлены, но M3 ещё нельзя
считать завершённым до PPO и прохождения проверочного критерия качества. На Windows
с RTX 4060 проверены официальный PyTorch с CUDA и частичный BC до контрольной точки эпохи 35;
незавершённый запуск был штатно остановлен без изменения Git. GUI не подключён
ни к клеточной, ни к полигональной политика; C++ ONNX получение вывода модели перенесён в M6.
Текущая клеточная модель несовместима с динамическим полигональным пространством действий и
не выдаётся за полигональную.
