# Текущее состояние

Проверено 2026-09-19.

В A8 удалён унаследованный настольный клеточный редактор. Единственное окно
показывает полигональную задачу и проверенное решение; версии форматов обмена и
замороженные исследовательские данные не менялись. Подробности решения приведены
в [ADR-0016](decisions/0016-retire-legacy-desktop.md).

Локально пройдены 44/44 проверки чистого раскроя, 46/46 проверок полного режима
без графического интерфейса и 52/52 проверки настольной сборки с ONNX.
Настольная сборка без ONNX прошла 10/10 проверок; полный Python-набор — 61/61.
Обе настольные сборки запущены без ошибки запуска. Архитектурный и языковой
контроль проходят; замороженный манифест M6.1 сохранил прежний SHA-256.

## Поддерживаемые контуры

- Windows Debug приложение собирается MSVC с Qt 6.9.3 без `AIPackaging_Math`.
- Проект использует C++20, CMake, Qt 6 и независимый от Qt модульный решатель.
- Клеточная модель остаётся исследовательским контуром без графического
  редактора; настольное приложение использует только полигональный контур.
- Независимый `AIPackaging_Solver` поддерживает пять воспроизводимых базовых алгоритмов:
  `input-first-fit`, две сортировки с размещением снизу слева, случайный поиск с
  заданным начальным значением и лучевой поиск.
- `AIPackaging_Cli` читает `grid_problem` v1 и сохраняет `grid_solution` v1 с
  независимо проверяемыми размещения, целевая функция и метриками.
- `GridLearningEnvironment` предоставляет постоянный каталог действий, маска,
  наблюдение v1, компактный траектория API и точный вознаграждение v1.
- Python-пакет `aipackaging-ml` предоставляет подобный Gymnasium API, генератор профилей
  `small`/средний и модуль проверки `grid_dataset`/`grid_trajectory` v1.
- Канонический набор данных содержит 768 задач и 3840 траекторий базовых алгоритмов; он
  генерируется локально в игнорируемом `artifacts/datasets/grid-v1`.
- Реализован конвейер M3: иерархическая политика «актор-критик», BC по
  экспертным траекториям, PPO,
  многопроцессная обработка траектория, нейросетевой/гибридный средство запуска, решение v2 и двухчастный ONNX.
- Реализован полигональный контур M4: строгий JSON, отрезки, дуги, кривые Bézier, микронные кольца,
  внешние границы и отверстия, NFP-кандидаты, пять базовых алгоритмов и повторную проверку.
- `PolygonLearningEnvironment` предоставляет динамические действия и
  растровое наблюдение 4×128×128; Python умеет создавать и проверять пробный
  набор данных.
- Проверенный пробный полигональный набор данных содержит 24 задачи и 120
  траекторий базовых алгоритмов;
  SHA-256 манифест: `da53ac408c2ec715205d11931cc0690a706ef153791aafe19fb43962b76cbc5f`.
- Настольное приложение содержит полигональную рабочую область со строгой
  загрузкой задачи, базовыми и нейросетевыми режимами, отменой, просмотром
  колец и сохранением только независимо проверенного результата.
- В A6 полигональный прикладной контроллер выделен в независимую цель
  `AIPackaging_Application`. Он больше не знает о Qt, JSON, файловой системе,
  `PolygonEnvironment` и конкретном поисковом API.
- `AIPackaging_DesktopInfrastructure` содержит локальный шлюз документов,
  проверяемую базовую внутреннюю реализацию и `StdThreadNestingJobRunner`.
  Поток, отмена и ограничение частоты уведомлений больше не принадлежат контроллеру.
- GUI использует только прикладные структуры данных; все точечные исключения A6

- Приложение показывает только полигональные задачи и решения; клеточный
  редактор `Board/Figure` удалён. Клеточные исследовательские API, CLI и наборы
  данных продолжают работать без графического интерфейса.
- Полигональная рабочая область показывает раскладку, но не редактирует
  контуры и не позволяет вручную перемещать детали.

  Масштаб клетки в миллиметрах старым форматом не задан; автоматического
  преобразования нет. Исходные пользовательские файлы не изменяются.

## Ограничения ML

M6.2 предоставляет полигональное наблюдение v2, иерархическую модель PyTorch,
вознаграждение по целевой функции, возобновляемые BC/PPO и проверяемые режимы
`greedy`, `best-of` и `hybrid`. Канонический восьмичасовой эксперимент на
Windows CUDA завершён и зафиксирован без изменения весов. На 64 тестовых
задачах гибрид получил 14 побед, 50 равенств и ни одного поражения относительно
`random-left-bottom/64`; `usedLength` улучшен в восьми задачах. Критерий M6.2
пройден. В M6.3 выбранная контрольная точка экспортирована двумя графами ONNX и
подключена к CLI и полигональной вкладке через отдельную реализацию на CPU.
Комплект выбирается пользователем и повторно проверяется по SHA-256. На
замороженной тестовой выборке гибрид получил 13 побед, 51 равенство и ни одного
поражения; в восьми задачах улучшен `usedLength`. Критерий M6.3 также пройден.

Подробности и хеши приведены в
[отчёте M6.2](experiments/m6-2-polygon-policy-2026-09-16.md).
Результаты развёртывания приведены в
[отчёте M6.3](experiments/m6-3-polygon-onnx-2026-09-19.md).

Код обучения, манифест локального запуска и ONNX-экспорт добавлены, но M3 ещё нельзя
считать завершённым до PPO и прохождения проверочного критерия качества. На Windows
с RTX 4060 проверены официальный PyTorch с CUDA и частичный BC до контрольной точки эпохи 35;
незавершённый запуск был штатно остановлен без изменения Git. GUI не подключён
к клеточной политике; полигональная политика подключена в M6.3 через прикладной
порт без зависимости контроллера от ONNX Runtime.
Текущая клеточная модель несовместима с динамическим полигональным пространством действий и
не выдаётся за полигональную.

## Повышение надёжности R3

Запись клеточного и полигонального решения теперь завершается во временном
файле рядом с назначением и только после этого заменяет прежний результат.
Отказ записи или замены сохраняет прежние байты. Фоновый полигональный поиск
освобождает идентификатор запуска до публикации итогового события, поэтому
обработчик может сразу начать следующую работу. Переходы
`PolygonLearningEnvironment` публикуются только после успешного построения
каталога и наблюдения.

Прерванная эпоха BC откатывается к последней согласованной контрольной точке;
автоматическое продолжение старой точки без отметки завершённой эпохи
отклоняется. Замороженные веса, геометрия, версии форматов обмена и набор M6.1
не менялись. В GitHub Actions добавлены отдельные задания для настольного Qt/ONNX
и Linux с проверкой памяти и неопределённого поведения. До отправки в удалённый репозиторий
эти новые задания остаются непроверенными в облаке.
