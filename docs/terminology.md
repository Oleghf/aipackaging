# Терминология проекта

## Основное правило

Документация, комментарии, диагностические сообщения и пользовательский текст
пишутся по-русски. При первом упоминании понятия сначала указывается русский
термин, а затем, если это помогает найти исходный контракт или команду, — точное
английское имя в `моноширинном начертании` либо в скобках.

Имена API, классов, полей JSON, команд, алгоритмов, файлов и форматов не
переводятся. В обычном тексте они оформляются как машинные литералы, например
`GridEnvironment`, `actionMask`, `input-first-fit` и `polygon_problem`.

Официальные названия технологий и общепринятые сокращения также сохраняются:
AIPackaging, C++, Qt, CMake, CTest, Python, PyTorch, NumPy, ONNX, JSON, Clipper2,
Git, Windows, Linux, CUDA, BC, PPO, NFP, DXF, SVG и SHA-256. Архитектурные
сокращения API, ABI, DTO, CI, MVP и RTTI употребляются после русского пояснения.

Новый английский термин разрешается только вместе с русским объяснением и после
добавления в машинный глоссарий
`tools/language/russian-prose-rules.json`.

| `runtime` | механизм выполнения |
| `cache` | кэш |
| `manifest` | манифест |

| `desktop` | настольное приложение |

| `placement` | размещение |

| `full` | полное решение |
| `validation` | проверка |
| `verifier` | модуль проверки |
| `replay` | повторное проигрывание |
| `worker` | рабочий процесс |

`чекпоинт` и `бэкенд` не используются.

## Текст и машинные контракты

Перевод человекочитаемого текста не должен менять:

- имена полей, значения перечислений и версии JSON-контрактов;
- имена целей сборки, команд и параметров командной строки;
- пути, хеши, формулы и зафиксированные результаты экспериментов;
- типы исключений, коды возврата и поведение программ.

Если точное английское имя является частью объяснения, его нужно выделить как
код: «цель сборки `AIPackaging_Search`», «поле `expertTrajectoryId`», «команда
`verify-polygon-dataset`».
