# План разработки

Оценки рассчитаны на одного разработчика с ИИ-помощником и не являются
обязательством по срокам. Основная платформа приёмки — Windows 11.

## Завершённые этапы

| Этап | Результат |
|---|---|
| M0 | Воспроизводимая сборка, тесты и первый базовый коммит |
| M1 | Клеточное ядро, пять базовых алгоритмов, JSON и CLI |
| M2 | Клеточная обучаемая среда и воспроизводимый набор данных |
| M4 | Полигональная геометрия, NFP, поиск и точный валидатор |
| M5 | Полигональный раскрой в настольном приложении |
| M6.1 | Замороженный полигональный набор из 384 задач и 1920 траекторий |
| M6.2 | Обученная полигональная политика BC/PPO и успешная тестовая оценка |
| M6.3/A7 | Комплект ONNX и получение вывода в C++ без Python |
| A1–A6 | Модульная архитектура, проверки зависимостей и прикладные порты |
| A8 | Вывод унаследованного клеточного настольного редактора |
| R2–R5 | Ревью и устранение подтверждённых дефектов надёжности |
| U1 | Дружелюбное рабочее место технолога версии `0.10.0` |
| M7.1 | Редактируемая модель, строгий черновик и восстановление версии `0.11.0` |
| M7.2 | Строгий импорт текстового DXF и пошаговый мастер версии `0.11.0` |
| M8.1 | Команды, числовые формы и история редактора версии `0.12.0` |
| M8.2 | Интерактивные инструменты полотна, привязки и диагностики версии `0.12.0` |
| M8.3 | Стабилизация крупных документов и локальная приёмка редактора версии `0.12.0` |

Клеточный M3 оставлен как замороженная исследовательская ветка: модель,
конвейер BC/PPO и экспорт реализованы, но первоначальный критерий качества
клеточного эксперимента не закрывался. Развитие продукта продолжилось через
полигональную политику M6.2–M6.3.

## M7 — редактируемый документ и импорт DXF

Версия: `0.11.0`. Статус: завершён.

### M7.1 — модель документа — завершён

- добавлена независимая от Qt редактируемая модель листа, деталей, колец и
  сегментов;
- используются стабильные внутренние идентификаторы;
- хранятся признаки `dirty`, `valid`, `running` и структурированные диагностики;
- введён локальный `aipackaging.polygon_draft` v1 для неполной геометрии;
- строгий `polygon_problem` v1 сохраняется только после полной проверки;
- добавлены атомарное автосохранение и предложение восстановления черновика.

### M7.2 — импорт DXF — завершён

Первый выпуск принимает текстовый DXF и поддерживает `LINE`, `LWPOLYLINE`,
`POLYLINE`, дуги по коэффициенту выпуклости `bulge`, `ARC`, `CIRCLE` и базовые кубические нерациональные
`SPLINE`.

Мастер импорта:

- определить единицы по `$INSUNITS` или запросить их у пользователя;
- предоставить выбор слоёв;
- показать распознанные цепочки, разрывы и неподдерживаемые сущности;
- не замыкать открытые цепочки молча;
- предложить назначение внешних колец и отверстий;
- позволить задать идентификаторы, количества и повороты;
- создать корректную задачу либо сохранить черновик.

Внутренние типы DXF не выходят из адаптера импорта. `INSERT`, размеры,
штриховки, текст, изображения и 3D-геометрия не входят в первый выпуск.

### Критерий M7

Одинаковый DXF даёт побайтово одинаковый `polygon_problem`. Валидный результат
импорта проходит существующий точный валидатор, а незавершённый документ можно
безопасно сохранить и восстановить как черновик.

## M8 — полигональный редактор

Версия: `0.12.0`. Статус: локально завершён; публичный выпуск ожидает внешнего CI.

### M8.1 — команды и история — завершён

- реализованы атомарные команды создания, удаления, переименования и
  дублирования типов деталей;
- числовые формы изменяют лист, количества, повороты, производственные
  параметры, кольца, отверстия, сегменты и служебные точки кривых;
- отмена, повтор и чистая точка последнего пользовательского сохранения
  отделены от автосохранения;
- история ограничена 200 транзакциями, не переиспользует удалённые `EntityId`
  и удаляет ветвь повтора после нового изменения;
- непрерывные изменения с одним идентификатором жеста объединяются в одну
  транзакцию для будущего перетаскивания M8.2;
- старое решение после изменения остаётся доступным для просмотра как
  устаревшее, но не сохраняется.

Документ нельзя изменять во время поиска. Решатель получает неизменяемый снимок
только после полной проверки.

### M8.2 — инструменты полотна — завершён

- добавлены одиночный, множественный и рамочный выбор исходных сущностей;
- точки, сегменты, контуры, детали и группы перемещаются одной объединённой
  транзакцией с плавным локальным предварительным просмотром;
- на полотне создаются внешние контуры, отверстия, отрезки, направленные дуги
  и кубические кривые Bézier;
- сетка и привязки к начальной вершине, конечным точкам, центрам дуг и сетке
  учитывают экранный допуск и временно отключаются клавишей `Alt`;
- исходная задача и последнее решение показываются в раздельных режимах;
- направления цепочек, управляющие точки и связанные диагностики видны на
  полотне, а вкладка «Проблемы» синхронизирует выбор с деревом;
- только замыкание открытой цепочки отрезком и удаление вырожденного сегмента
  предлагаются как однозначные исправления с подтверждением пользователя.

Ручное перемещение деталей готовой раскладки, экспорт обратно в DXF и
построение траектории реза в M8 не входят.

## M8.3 — стабилизация редактора

Статус: локально завершён.

- редакции истории хранятся как совместно используемые неизменяемые снимки;
- автосохранение вынесено в последовательный рабочий поток с объединением
  ожидающих поколений;
- полотно использует временный пространственный индекс, а дерево перестраивается
  только при смене редакции;
- точные ошибки геометрии связываются с `EntityId` структурированным кодом и
  исходными индексами, без анализа текста;
- добавлены крупные документы `editor-500` и `editor-1000`, случайные
  последовательности команд, Release-ворота производительности и примеры
  черновиков;
- локальная матрица Windows и ручные сценарии зафиксированы в
  [отчёте приёмки](experiments/m8-3-editor-acceptance.md).

## Итоговый критерий

Текущий этап — R1: локальный кандидат `1.0.0`. Порядок работ — блокирующие
проблемы, полировка интерфейса, автономные руководства, безопасная очистка,
ZIP и приёмка чистой Windows. Статус — в [описании поставки](release.md).
Публикация требует отдельного разрешения, условий распространения и
успешного внешнего CI. Следующий производственный этап пока не утверждён.

Технолог без ручного редактирования JSON может создать задачу или импортировать
DXF, исправить контуры и отверстия, настроить производственные параметры,
восстановить незавершённую работу, запустить раскрой и сохранить независимо
проверенное решение.

Форматы существующих задач и решений, замороженный набор M6.1 и комплект модели
M6.3 остаются совместимыми на всех этапах.
