# ADR-0007: Отдельная полигональная рабочая область в настольном приложении

- Статус: заменено ADR-0016 и ADR-0019
- Дата: 2026-09-10

## Контекст

Существующий Qt-экран редактирует клеточные `Board/Figure`, тогда как M4 хранит
авторитетную геометрию в независимом `AIPackaging_Solver`. Преобразование
полигонов обратно в клетки потеряло бы кривые, отверстия, миллиметровые единицы
и точность валидатора. Доступная ONNX-модель также является клеточной и не
совместима с динамическим полигональным пространством действий.

## Решение

Настольное приложение содержит две независимые вкладки. Клеточный прототип сохраняет прежнюю
модель, а полигональная вкладка работает по цепочке
`Qt GUI -> PolygonWorkspaceController -> IPolygonSolverBackend -> PolygonEnvironment`.
Графический интерфейс получает только модель представления колец, метрик и
статуса и не выполняет проверку столкновений.

Базовый алгоритм запускается в принадлежащем контроллеру `std::jthread`. Ход выполнения и
завершение доставляются в поток Qt через поставленную в очередь функцию
обратного вызова. Каждый запуск имеет
идентификатор, поэтому запоздалые сообщения не могут заменить более новое
состояние. Отмена опрашивается на безопасных границах поиска и не выдаётся за
ограничение времени. Отменённое частичное решение можно увидеть, но нельзя сериализовать как обычный
результат.

Полное или частичное неотменённое решение публикуется и становится доступным
для сохранения только после повторного `PolygonSolutionValidator`. Формат обмена
`polygon_solution` v1 не меняется.

## Последствия

M5 предоставляет рабочий полигональный базовый алгоритм в приложении без миграции
старого редактора. Интерактивное изменение контуров, DXF/SVG и траектория инструмента остаются
отдельными задачами. Интерфейс `IPolygonSolverBackend` является точкой
подключения будущего нейросетевого или гибридного получения вывода модели, но
текущая клеточная ONNX-модель в полигональной рабочей области не используется.
