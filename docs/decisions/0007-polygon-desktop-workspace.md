# ADR-0007: Отдельный полигональный workspace в desktop

- Статус: принято и реализовано
- Дата: 2026-09-10

## Контекст

Существующий Qt-экран редактирует клеточные `Board/Figure`, тогда как M4 хранит
авторитетную геометрию в независимом `AIPackaging_Solver`. Преобразование
полигонов обратно в клетки потеряло бы кривые, отверстия, миллиметровые единицы
и точность валидатора. Доступная ONNX-модель также является клеточной и не
совместима с динамическим полигональным action space.

## Решение

Desktop содержит две независимые вкладки. Клеточный прототип сохраняет прежнюю
модель, а полигональная вкладка работает по цепочке
`Qt GUI -> PolygonWorkspaceController -> IPolygonSolverBackend -> PolygonEnvironment`.
GUI получает только presentation-модель колец, метрик и статуса и не выполняет
collision-проверки.

Baseline запускается в принадлежащем контроллеру `std::jthread`. Progress и
завершение доставляются в Qt-поток через queued callback. Каждый запуск имеет
идентификатор, поэтому запоздалые сообщения не могут заменить более новое
состояние. Отмена опрашивается на безопасных границах поиска и не выдаётся за
timeout. Отменённый partial можно увидеть, но нельзя сериализовать как обычный
результат.

Полное или частичное неотменённое решение публикуется и становится доступным
для сохранения только после повторного `PolygonSolutionValidator`. Wire-формат
`polygon_solution` v1 не меняется.

## Последствия

M5 предоставляет рабочий полигональный baseline в приложении без миграции
старого редактора. Интерактивное изменение контуров, DXF/SVG и toolpath остаются
отдельными задачами. Интерфейс `IPolygonSolverBackend` является точкой
подключения будущего neural/hybrid inference, но текущая клеточная ONNX-модель в
полигональном workspace не используется.
