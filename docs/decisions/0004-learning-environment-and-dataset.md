# ADR-0004: Обучаемая среда и клеточный набор данных M2

- Статус: принято и реализовано
- Дата: 2026-09-09

## Контекст

M1 дал единые кандидаты, целевую функцию и валидатор, но базовые алгоритмы выполнялись целиком
в C++. Для обучение по экспертным примерам и RL нужен пошаговый контракт, в котором индекс
действия стабилен, недопустимые действия маскируются, а наблюдения и вознаграждение можно
воспроизводить независимо от процесса генерации.

## Решение

`GridLearningEnvironment` при создании эпизода строит неизменный каталог всех
геометрически помещающихся действий в порядке
`part/instance/rotation/column/row`. После размещений меняется только
`action_mask`. Индекс вне каталога, замаскированное действие и шаг после
завершения отклоняются до изменения состояния. Эпизод завершается полным
размещением либо отсутствием допустимых действий и никогда не использует
`truncated`.

наблюдение v1 состоит из доступный только для чтения NumPy-массивов занятость, масок и признаков
экземпляров, ориентаций и кандидатов, оставшиеся экземпляры, действие маска и семи
нормализованных компонент целевая функция. Среда v1 ограничена 4096 клетками,
количеством экземпляров не больше площади листа и 1 000 000 действий. Эти
ограничения относятся к ML-контракту, а не к валидности M1-задачи.

вознаграждение v1 равен нормализованной дельте смешанного ранга:

```text
A = rows × columns; B = A + 1; W = columns
rank(s) = ((((placedParts × B + placedCells)
             × (W + 1) + (W - usedLength))
             × B + largestExtraRectangleArea)
             × B + (A - fragmentationPenalty))
reward = (rankAfter - rankBefore) / rankUpperBound
```

Таким кодированием число деталей строго важнее площади, а площадь — качества
остатка. терминал добавочное вознаграждение отсутствует. `info` сохраняет оба ранга и дельты
компонент.

Python-пакет `aipackaging-ml` предоставляет `GridNestingEnv` через pybind11 без
Gymnasium и PyTorch. Генератор строит разрешимые задачи с 4-связными полимино
профилей `small`/средний. начальное значение генератора задачи выводится из её полного стабильного адреса.
Каждая задача получает пять M1-траекторий и ссылку на лучшую по M1-порядку.

`grid_dataset` v1 ссылается на канонические `JSONL.gz` части набора данных задач и траекторий,
их SHA-256, версии контрактов и конфигурацию. Gzip записывается с `mtime=0`,
наблюдения восстанавливаются повторное проигрывание действий, а инвариантный к повороту хеш семейства
не может пересекать `train`/проверка/тест.

## Последствия

Одинаковые начальное значение генератора и ревизия кода дают побайтово одинаковый набор данных независимо от числа
рабочих процессов. Диагностические времена M1 при записи ML-траектории обнуляются,
поскольку фактическое время не воспроизводим; детерминированные счётчики сохраняются.
Полные наборы данных находятся в игнорируемом `artifacts/datasets/grid-v1`, а Git
содержит код, схемы и малый пробный тестовый пример. Обучение и выбор модели остаются M3.
