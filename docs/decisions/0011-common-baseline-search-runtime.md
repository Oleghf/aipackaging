# ADR-0011: единый механизм выполнения базовых алгоритмов поиска

Статус: принято.

## Контекст

После A3 клеточный и полигональный поиск находились в одной цели сборки, но независимо
реализовывали порядок, случайные перестановки, лучевой поиск, ограничение времени, метрики и метаданные.
Только полигональный API поддерживал ход выполнения и совместную отмену. Такое
дублирование затрудняло добавление новых базовых алгоритмов и создавало риск различий в
семантике остановки и диагностических счётчиков.

Геометрия двух сред при этом принципиально различается: клеточный контур отдельно ранжирует
кандидаты размещения снизу слева, а полигональный получает уже отсортированный динамический
NFP-каталог. Их состояния, целевая функция и обработка ограничения каталога также не
должны становиться общими типами.

## Решение

- `SearchContracts` владеет общими `SearchProgressStage`, `SearchProgress` и
  `SearchExecutionControl`.
- `Search` содержит закрытый `SearchRuntime`, общий порядок и жизненный цикл
  упорядоченного, случайного и лучевого поиска.
- клеточный и полигональный контуры подключаются к жизненному циклу небольшими адаптерами времени компиляции,
  которые сохраняют состояния, геометрию, выбор кандидата, компаратор и
  независимую валидацию своей предметной области.
- механизм выполнения не создаёт потоки. Функции обратного вызова отмены и хода выполнения выполняются
  синхронно в потоке вызывающего кода; их исключения не перехватываются.
- Отмена проверяется только на безопасных границах до следующей мутации и имеет
  приоритет над ограничением времени, если обе причины наблюдаются одновременно.
- Отмена остаётся признаком результата выполнения и не добавляется в `SolveStatus`
  или форматы обмена. Ограничение времени и детерминированный бюджет сохраняют прежние статусы.
- Монотонные часы внедряются только во внутренний механизм выполнения: рабочая реализация использует
  `steady_clock`, а модульные тесты управляют временем без ожидания.
- Прежние полигональные имена хода выполнения и управления сохраняются как
  псевдонимы типов. Клеточный контур получает
  симметричный `runGridProblem`; старые `solve*` остаются фасадами.

## Последствия

Алгоритмы обеих сред используют один механизм начального значения генератора,
остановки, хода выполнения, метрик и метаданных, но механизм выполнения не
знает о клетках, NFP или растровой целевой функции.
Форматы обмена и API Python не меняются. Новые базовые алгоритмы смогут переиспользовать
жизненный цикл выполнения, не копируя инфраструктуру.

Нулевая стоимость абстракции достигается шаблонным внутренним жизненным циклом. Его
требования к адаптеру остаются закрытой деталью `AIPackaging_Search` и не
становятся новым публичным каркасом API.
