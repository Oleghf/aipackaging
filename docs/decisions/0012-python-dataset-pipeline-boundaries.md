# ADR-0012: границы конвейеров наборов данных Python

Статус: принято.

## Контекст

Клеточный и полигональный наборы данных независимо реализовывали канонический
JSON, gzip, SHA-256, проверку полей и путей к частям набора данных. Модули
одновременно отвечали за генерацию задач, траектории базовых алгоритмов, запись
манифеста и полное повторное проигрывание. Загрузчик M3 импортировал закрытую
функцию из публичного `dataset.py`, а CLI напрямую связывал обработку данных и
сценарии ML. Это повышало риск расхождения форматов и случайного появления
PyTorch в базовой установке.

Рабочий конвейер обработки M6.1 существовал только как незавершённое рабочее
дерево. A5 не смешивал это функциональное различие с архитектурным
рефакторингом стабильного A4.

## Решение

- Внутренний пакет `aipackaging_ml.datasets` владеет каноническими JSON/JSONL,
  детерминированным gzip, SHA-256, безопасными путями к частям набора данных и
  атомарным вводом-выводом кэша.
- Клеточный и полигональный контуры разделены на генерацию, траектории,
  повторное проигрывание, проверку и сборку манифеста. Геометрия, пространство
  действий, проверка и компаратор остаются в C++.
- `dataset.py`, `generator.py`, `polygon_dataset.py`, `contracts.py` и
  `environment.canonical_json` сохраняют прежние пути импорта как фасады.
- `training_data` читает части набора данных через общее открытое внутреннее
  средство чтения, а не через закрытое имя фасада.
- Обработчики CLI разделены на работу с наборами данных и ML. Зависимости ML
  импортируются только после выбора соответствующей команды.
- Средство проверки архитектуры определяет владельца Python по полному пути
  модуля и самому длинному префиксу. Общий модуль данных не зависит от нативной
  привязки, среды или обучения, а контур наборов данных не зависит от модели,
  обучения, оценки или PyTorch.
- Кэш v1 является внутренней оболочкой с идентификатором, отпечатком и полезной
  нагрузкой. A5 проверяет его атомарность, но не добавляет `--resume` в публичный
  CLI.

## Последствия

Клеточные и полигональные контракты v1 сохраняют сигнатуры, команды и точные
байты при одинаковой ревизии сборки. Базовая установка продолжает требовать
только NumPy и нативную привязку Python/C++. Рабочий набор данных v2,
возобновление и сравнительное испытание M6.1 подключаются к выделенным модулям
без повторной реализации JSON, gzip, хеширования и кэша.

Откат возможен заменой тонких фасадов прежними монолитными реализациями: форматы
обмена и привязки Python/C++ не изменены.
