# ADR-0015: развёртывание полигональной политики через ONNX

Дата: 2026-09-17

Статус: принято

## Контекст

Полигональная политика M6.2 обучена в Python, но настольное приложение не должно
зависеть от Python или PyTorch. Пространство действий полигональной среды меняется
после каждого размещения, поэтому модель не может безопасно возвращать произвольные
координаты. Комплект модели поставляется отдельно от приложения и должен быть
проверен до первого вычисления.

## Решение

- Политика экспортируется двумя графами ONNX с набором операций 23:
  `encoder.onnx` и `placement-head.onnx`.
- Метаданные `aipackaging.polygon_policy` v2 фиксируют версии контрактов,
  размеры растров, динамические оси и SHA-256 всех частей.
- `AIPackaging_OnnxInference` является отдельной целью сборки. Она зависит от
  полигональной обучаемой среды и ONNX Runtime, но прикладной слой и ядро раскроя
  от ONNX Runtime не зависят.
- ONNX Runtime 1.29.0 выполняет вычисления на CPU последовательно и с одним
  потоком. Это уменьшает различия между машинами и не требует CUDA на компьютере
  пользователя.
- Действие всегда выбирается из текущего каталога
  `PolygonLearningEnvironment`; после каждого прогона решение проверяет
  `PolygonSolutionValidator`.
- Python и C++ используют `SplitMix64`, производное начальное значение каждого
  прогона и одинаковое последовательное суммирование стабилизированного
  `softmax`. Жадное равенство разрешается минимальным индексом каталога.
- В режиме `Neural` ошибка модели является ошибкой запуска. В режиме `Hybrid`
  сначала вычисляется проверенное решение `random-left-bottom/64`; при отказе
  модели оно возвращается с происхождением `HybridFallback` и явной диагностикой.
  Если модель исправна, выбор базового результата как лучшего сохраняет
  происхождение `Hybrid`.
- Контроллер получает только `PolygonModelHandle`. Файлы, сеансы ONNX Runtime и
  проверка комплекта находятся за `IPolygonModelGateway` и
  `IPolygonNestingBackend`.

## Последствия

Настольное приложение может применять политику без Python, а отключение
`BUILD_ONNX_BACKEND` полностью исключает ONNX Runtime из чистой сборки раскроя.
За это приходится поставлять внешнюю библиотеку ONNX Runtime и отдельно хранить
проверяемый комплект модели. Обновление графов требует нового общего SHA-256 и
повторной проверки совместимости, даже если идентификатор модели не изменился.

## Отклонённые варианты

- Встраивание обученных весов в исполняемый файл затрудняет обновление и аудит.
- Получение вывода через локальный процесс Python нарушает автономность
  настольного приложения.
- Возврат моделью координат в обход каталога ослабляет геометрические гарантии.
- Неявная замена нейросетевого режима базовым алгоритмом скрывает отказ модели.
