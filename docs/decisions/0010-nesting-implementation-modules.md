# ADR-0010: границы реализации модулей раскроя

- Статус: принято
- Дата: 2026-09-11

## Контекст

После A2 общие контракты имели отдельного владельца, однако восемь единиц
трансляции геометрии, поиска, JSON и обучения оставались в одном `SolverImpl`.
Из-за этого любой потребитель получал полный набор реализаций и внешних
зависимостей, а средство проверки включений заголовков не могло доказать отсутствие связей между слоями.

## Решение

Разделить реализацию модульного монолита на:

- `SearchContracts` для `SolverKind`, `SolverConfig` и строковых преобразований;
- `GridCore` и `PolygonCore` для состояния, допустимости, кандидатов, целевой функции
  и независимой валидации;
- `Search` для клеточных и полигональных базовых алгоритмов и компараторов;
- `Json` для строгих адаптеров форматов обмена;
- `Learning` для пошаговых сред.

`Json` может зависеть от `SearchContracts`, но не от алгоритмов `Search`.
`Learning` зависит только от геометрии и ядра среды. Clipper2 остаётся
закрытой зависимостью `PolygonCore` и используется только при генерации кандидатов;
nlohmann/json остаётся закрытой зависимостью модуля JSON. Привязка Python/C++ является
адаптером над поиском, JSON и обучением.

`SolverImpl` становится `INTERFACE`-агрегатором, а `Solver` сохраняет прежние
плоские заголовки для прикладного слоя и GUI до A6. Канонические заголовки,
пространство имён, форматы обмена, порядок действий и вычисление целевой функции
не меняются.

## Последствия

Положительные:

- полигональное обучение развивается без зависимости от JSON и механизма выполнения базовых алгоритмов;
- внешние библиотеки локализованы и проверяются автоматически;
- регрессия определяется тестом конкретного владельца;
- A4 может переработать жизненный цикл поиска без затрагивания геометрии и обучения.

Отрицательные:

- увеличивается число статических библиотек и исполняемых файлов тестов;
- до A6 сохраняются две цели сборки совместимости;
- интеграционные тесты повторного проигрывания обучения дополнительно связывают
  поиск и JSON, хотя рабочее обучение от них не зависит.

## Откат

Каждую цель сборки реализации можно отдельно вернуть в агрегатор `INTERFACE`.
перенаправляющие заголовки и неизменные контракты форматов обмена позволяют выполнить откат без
миграции прикладного слоя, GUI, CLI, Python или сохранённых наборов данных.
