# ADR-0005: Иерархическая клеточная политика M3

- Статус: принято, реализация и эксперимент выполняются
- Дата: 2026-09-10

## Контекст

На задачах M2 постоянный каталог содержит от сотен до 51 тысячи действий.
Плоская классификация всего каталога расходует память на множество позиций
невыбранных деталей и плохо переносится на другой размер задачи. При этом любая
политика обязана выбирать только действие из авторитетной C++ `actionMask`.

Первоначально эталонный GPU-запуск планировался в WSL2. После изменения локальной
политики хоста официальный CUDA PyTorch также проверен непосредственно в Windows;
выбор ОС не меняет контракты начального значения генератора, контрольной точки и оценки.

## Решение

`HierarchicalGridPolicyV1` один раз кодирует занятость, формы, признаки деталей
и целевую функцию. Актор затем выбирает допустимый экземпляр, его допустимый поворот и
оценивает только позиции этой пары. Вероятность действия факторизуется в сумму
трёх логарифмов вероятностей. Критик использует общее представление состояния.

Обучение по экспертным примерам использует только экспертные траектории
обучающей выборки `train`. PPO
оптимизирует неизменённое вознаграждение v1 с `gamma=1`; дополнительное
формирование вознаграждения и добавочное терминальное вознаграждение запрещены.
Геометрические шаги выполняются четырьмя рабочими процессами,
а выбор действий централизован, что сохраняет стабильный порядок результатов.

Экспорт состоит из `encoder.onnx` и `placement-head.onnx`. Метаданные фиксируют
версии контрактов, ограничения, хеши и правило разрешения равенства. Получение
вывода модели в Python может вернуть нейросетевое решение v2 либо в гибридном
режиме выбрать лучший результат между
16 траектория политики и `random-left-bottom/64`. Любой результат независимо
проверяется C++-валидатором.

Поддерживаемая среда обучения — Windows либо Ubuntu 24.04 в WSL2 с Python
3.12–3.13 и CUDA. Конкретная ОС записывается в метаданные запуска. Настольное приложение
не зависит от Python, PyTorch или механизма выполнения ONNX; загрузка ONNX в C++ относится к
M5.

## Последствия

Модель ограничена профилями `small`/средний: лист до 24×24, 30 экземпляров, габарит
детали до 12 и каталог до 65 536 действий. Более крупная задача не считается
геометрически неверной: нейросетевое средство запуска отказывает по совместимости, после чего
может использоваться базовым алгоритмом.

M3 считается исследовательски завершённым только после замороженного отчёта по
тестовой выборке: 128 валидных полных гибридных решений, ни одного проигрыша
алгоритму `random-left-bottom/64`, не менее шести
лексикографических улучшений и хотя бы одного уменьшения `usedLength`.
