# Качество и проверка

## Общий принцип

Каждое изменение проверяется на том уровне, который оно затрагивает. Редактура
документации не требует длительного повторного проигрывания наборов данных, а
изменение геометрии обязательно требует граничных и сквозных тестов.

## Стандартные команды

```powershell
python tools/run_checks.py documentation
python tools/run_checks.py language
python tools/run_checks.py format
python tools/run_checks.py architecture
python tools/run_checks.py nesting
python tools/run_checks.py headless
python tools/run_checks.py python
python tools/run_checks.py desktop-no-onnx --qt-dir <путь-к-Qt6Config>
python tools/run_checks.py desktop --qt-dir <путь-к-Qt6Config>
```

`python tools/run_checks.py all --qt-dir <путь-к-Qt6Config>` выполняет их
последовательно. Средство запуска не устанавливает зависимости и не очищает
каталоги сборки.

Назначение контуров:

- `documentation` — локальные ссылки, версии, этапы и хеши;
- `language` — русская терминология в документации, комментариях и сообщениях;
- `format` — сухая проверка `.clang-format` всех отслеживаемых собственных
  файлов C++;
- `architecture` — направления зависимостей C++, CMake и Python;
- `nesting` — чистое ядро, поиск, JSON и CLI;
- `headless` — ядро, прикладной слой и инфраструктура без Qt;
- `python` — привязка, наборы данных, обучение, экспорт и оценка;
- `desktop-no-onnx` — Qt и базовая настольная инфраструктура без ONNX;
- `desktop` — Qt, инфраструктура и ONNX для настольного приложения.

## Геометрия и поиск

Изменения нормализации, NFP, области зазора или валидатора должны покрывать:

- крайние и переполняющиеся координаты;
- границы листа, касание и положительный зазор;
- вогнутые кольца и самопересечения;
- отверстия внутри, снаружи и на границе внешнего кольца;
- повороты и симметричные ориентации;
- погрешность аппроксимации дуг и Bézier;
- стабильный порядок кандидатов обеих версий каталога;
- полные и лучшие частичные решения;
- повторную независимую проверку результата.

Отмена и ограничение времени проверяются на управляемых безопасных границах без
реального ожидания. Подключение пассивного уведомления не должно менять
детерминированный результат.

Полное сравнение каталогов на замороженном наборе выполняется до и после
изменения геометрии:

```powershell
python tools/regression/hash_polygon_catalogs.py `
  --dataset artifacts/datasets/polygon-v2 `
  --output artifacts/regression/polygon-catalogs-before.json
python tools/regression/hash_polygon_catalogs.py `
  --dataset artifacts/datasets/polygon-v2 `
  --expected artifacts/regression/polygon-catalogs-before.json
```

Средство проверяет точный индекс и действие каталога версии 1. Для версии 2
сохранённое действие ищется по содержимому, после чего переход повторно
проигрывается. Каждый полный каталог до действия и терминальный каталог
канонически сериализуются в поток SHA-256. Отчёт фиксирует число задач,
траекторий, состояний и действий; сам полный снимок каталогов в Git не входит.
Эталон Q2.6 для 1920 траекторий и 18 131 состояния: версия 1 —
`cfae11ebb1b402a58185c771f6317c57cc8e3db431e099f34e7cdfffe16d570e`,
версия 2 —
`ea63955f4149fd9a05ee5a6c6512a345219cc1aa3409b780ea4c9670d45a2f29`.

## Форматы и сохранение

Схемы JSON используют Draft 2020-12. Общий набор контрактных примеров должен
одинаково классифицироваться схемой, C++-разбором и доменным валидатором.
Проверяются неизвестные поля, версии, типы, ссылки, статусы, метаданные и
несовпадающие метрики.

Закрытые операции чтения JSON отдельно проверяют синтаксические ошибки, точный
набор полей, обязательные значения, конечность чисел и границы `int`,
`int64_t`, `uint64_t` и `size_t`. Декомпозиция загрузчиков не должна менять
предметные сообщения об ошибках или байты сериализации.

Разбор CLI тестируется отдельно от файловых операций и решателей. Для каждой
команды фиксируются значения по умолчанию, повторные параметры, числовые
границы, диагностические сообщения и коды завершения 0–3.

Сохранение решения, задачи и черновика атомарно заменяет файл только после
успешной записи во временный файл того же каталога. При отказе прежнее
содержимое остаётся побайтно неизменным, а временный файл удаляется.

Для `polygon_draft` v1 дополнительно проверяются точный набор полей, версия,
вид источника, метка UTC, поколение, отпечаток источника, уникальность всех
`EntityId` и строгое превосходство `nextEntityId`. Круговой проход должен быть
детерминированным и сохранять канонические байты.

Редактируемая модель отдельно проверяется без Qt и решателя: выдача и
непереиспользование идентификаторов, конечность координат, согласованность
вершин и сегментов, уникальность имён, размеры листа, количества, повороты и
разделение ошибок и предупреждений. Снимок для решателя публикуется только
после последующей точной нормализации.

## Python, данные и обучение

- Канонический JSON, JSONL и gzip должны быть побайтово воспроизводимы.
- Пути частей набора не могут выходить за его корень.
- Разделение обучающей, проверочной и тестовой выборок проверяется по хешу
  семейства.
- Траектории повторно проигрываются через нативный каталог действий и
  валидатор.
- Возобновление BC/PPO проверяет конфигурацию, набор данных, хеш контрольной
  точки, полную историю и подтверждённую границу состояния до изменения модели.
- Суммарный временной бюджет сохраняется между продолжениями, а незавершённая
  эпоха или операция обновления откатывается целиком.
- Старая клеточная точка без подтверждённой истории используется только для
  оценки и экспорта.
- Генерация частей агрегирует результаты в порядке плана независимо от порядка
  завершения рабочих процессов и истории возобновления.
- Тестовая выборка не используется для настройки модели.
- Длительное обучение и полная генерация запускаются только отдельной задачей.

## ONNX

Комплект модели принимается только после проверки формата, архитектуры, версий
контрактов, имён файлов, размеров и SHA-256. Python и C++ должны выбирать
одинаковые жадные и случайные действия при одинаковом начальном значении.
Допустимое абсолютное расхождение оценок PyTorch и ONNX равно `1e-5`.

Проверяются неверные формы, NaN, повреждённые файлы, отмена между действиями и
прогонами, а также обязательная точная проверка каждого решения.

## Настольное приложение

Qt-тесты выполняются без отображения окна с `QT_QPA_PLATFORM=offscreen`.
Диспетчер прикладного потока не выполняет функции синхронно, не выбрасывает
исключения и явно сообщает об отказе постановки события. Итоговая модель или
решение остаются во владении фонового средства до подтверждения получателем.
При отказе доставки результат освобождается без повтора и без синхронной
резервной передачи.

Проверяются:

- начальная и рабочая страницы;
- четыре пользовательских режима и расширенные настройки;
- отсутствие, фоновая загрузка, замена и ошибка модели;
- состояния загрузки, поиска, отмены, частичного и полного результата;
- недавние файлы, примеры и восстановление `QSettings`;
- карточка читаемого или повреждённого автоматического черновика;
- задержка автосохранения, поколения, ошибка записи и восстановление документа;
- предупреждение при изменившемся исходном файле и запрос при замене грязного
  документа;
- разделение `Ctrl+S` для документа и `Ctrl+Shift+S` для решения;
- выбор детали, координаты, легенда и доступные имена;
- закрытие приложения во время фоновой работы;
- отказ доставки, исключение обработчика и освобождение непереданного результата;
- масштабы 100 %, 150 % и 200 %, а также минимальное окно 1280×720.

Тесты настольной инфраструктуры разделены на независимо собираемые цели для
шлюзов и хранилища, внутренних реализаций раскроя и фоновых работ. Обе
настольные конфигурации выполняют полный доступный набор CTest и сравнение 20
решений CLI с эталоном.

Перед выпуском проводится ручная приёмка Windows 11 при тех же масштабах.

Ожидаемая матрица M7.1 содержит 45 проверок чистого ядра, 51 проверку полного
режима без графического интерфейса, 55 настольных проверок без ONNX, 60
настольных проверок с ONNX и 80 проверок Python.

## Неподвижные эталоны

Изменения, не затрагивающие соответствующий контракт, должны сохранять:

- семантические эталоны 20 решений CLI;
- SHA-256 манифеста M6.1
  `747ade28a858de2f1d484cdf6c942df07cb59af017eeb886f8c18d9105422c44`;
- SHA-256 выбранной контрольной точки
  `ff15a085836fa9c8e31e28ace360a91bc38dfbca926c2d3d6d332ff007151937`;
- идентичность комплекта модели
  `2c792b5b63b62c3b2f74207f9842300dc3cfc580c9655a15f98a3d850a23bb33`;
- версии публичных форматов и каталога действий.

## Автоматические задания

GitHub Actions проверяет Linux, Windows MSVC, Python 3.13, настольную сборку Qt
с ONNX и без него, а также AddressSanitizer и UndefinedBehaviorSanitizer для
чистого ядра Linux. Результат задания считается подтверждённым только после
фактического запуска опубликованного коммита.

Перед коммитом дополнительно выполняются `clang-format` для изменённых C++
файлов, диагностический `clang-tidy` и `git diff --check`.

Команда `language` дополнительно проверяет наличие русской шапки перед
классами, структурами, объявлениями и определениями функций, включая
удалённые и стандартные специальные функции. Точечное исключение допускается
только для точного пути и символа с обязательной причиной в конфигурации.
