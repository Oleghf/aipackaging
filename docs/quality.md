# Качество и оценка

## Сначала корректность

Раскладка допустима только при выполнении ограничений границ, пересечений,
зазора, преобразований и количества. Невалидная раскладка считается ошибкой и
не получает конкурентную оценку использования материала.

## Baseline-алгоритмы

Минимальный набор:

- текущий deterministic first-fit;
- сортировка по убыванию площади/габарита с bottom-left;
- лучший результат нескольких seeded random порядков;
- ограниченный beam search по тому же набору кандидатов.

Baseline и модель используют одинаковые кандидаты, валидатор, timeout и расчёт
целевой функции.

## Метрики

- доля валидных и полных решений;
- значение выбранной функции ценности остатка;
- площадь и размеры крупнейшего повторно используемого остатка;
- длина занятой полосы от выбранного края листа;
- фрагментация свободной области;
- использование материала как диагностическая, но не единственная метрика;
- занятая ширина/длина или envelope;
- wall-clock time и число проверенных кандидатов;
- inference time отдельно от geometry time;
- разрыв с лучшим известным решением или baseline;
- результаты по числу деталей и сложности контуров.

Бизнес-цель и порядок сравнения зафиксированы в ADR-0002. Основная метрика —
`usedLength`; ширина главного остатка равна `sheetWidth - usedLength`. Она должна
одинаково вычисляться для baseline, model evaluation и UI. Reward обучения может
иметь дополнительные нормализованные компоненты, но не должен менять порядок
оценки итоговых решений.

## Протокол данных

- В Git хранятся генераторы и малые распространяемые fixtures, но не датасеты.
- Версионируются схемы, генераторы, seed и preprocessing.
- Разделение выполняется по семействам форм или исходным заказам.
- Test set не используется при обучении и подборе гиперпараметров.
- Фиксируются происхождение данных и права.
- Нужны сложные случаи: тонкие элементы, почти касающиеся границы, вогнутость,
  повторы, симметрия, отверстия и экстремальные масштабы.

## Уровни тестирования

Unit tests покрывают нормализацию, offsets, преобразования, пересечения,
кандидаты, метрики и сериализацию. Property tests проверяют round-trip,
симметрию overlap и инварианты сгенерированных случаев. Golden tests фиксируют
малые задачи и ожидаемые метрики.

Model evaluation проверяет совместимость схем, seeded inference, соблюдение
action mask, fallback и точную post-validation. Каждый отчёт эксперимента
содержит revision кода, версии данных и среды, конфигурацию, seed, оборудование,
время обучения, бюджет оценки и per-instance результаты.
