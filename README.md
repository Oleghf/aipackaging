# AIPackaging

AIPackaging — исследовательский проект нейросетевой системы решения задачи
двумерной упаковки при раскрое листовых материалов. Целевая система должна
работать с деталями произвольной формы, включая криволинейные границы, вырезы и
отверстия.

Репозиторий содержит настольный клеточный прототип и независимое ядро
полигонального раскроя, работающее без графического интерфейса. Настольное
приложение предоставляет отдельные клеточную и полигональную вкладки; обученная
политика M3 пока остаётся клеточной.

## Направление разработки

Планируется гибридный решатель:

1. геометрическое ядро импортирует и нормализует детали;
2. оно формирует допустимые варианты размещения и маску действий;
3. нейросетевая политика выбирает деталь, ориентацию и вариант размещения;
4. точный валидатор гарантирует геометрическую корректность результата;
5. приложение вычисляет метрики и экспортирует раскладку.

Так нейросеть отвечает за глобальные решения, а геометрическая допустимость
остаётся детерминированной. Решение описано в
[ADR-0001](docs/decisions/0001-hybrid-neural-solver.md).

Первые эксперименты обучения проводятся на существующей клеточной модели.
Полигональная геометрия вводится после появления воспроизводимой среды,
базовых алгоритмов, метрик и цикла обучения.

## Текущие возможности

- интерактивный редактор и сцена клеточной упаковки;
- ручное размещение, перемещение, поворот, отмена и повтор действий;
- загрузка и сохранение пулов клеточных фигур;
- проверка границ поля и занятых клеток;
- детерминированное автоматическое размещение по правилу первого подходящего
  места (`first-fit`);
- независимое от Qt клеточное ядро решателя с пятью базовыми алгоритмами;
- интерфейс командной строки без графического интерфейса и версионированные
  JSON-контракты задачи и решения;
- пошаговая обучаемая среда с постоянным пространством действий и
  вознаграждением версии 1;
- привязки Python/C++ для Python 3.12–3.13 и воспроизводимый генератор траекторий
  базовых алгоритмов;
- иерархическая политика PyTorch с архитектурой «актор-критик», конвейер
  обучения BC/PPO и экспорт ONNX;
- нейросетевой выбор лучшего из нескольких запусков и безопасный гибридный
  режим с точной повторной проверкой;
- строгий полигональный JSON-контракт, отрезки, дуги, кривые Bézier и
  нормализация координат в микроны типа `int64`;
- динамические NFP-кандидаты, полигональные базовые алгоритмы и точный
  валидатор;
- среда Python `PolygonNestingEnv` и воспроизводимый пробный полигональный набор
  данных;
- рабочий формат `polygon_dataset` v2 с двумя профилями сложности, изоляцией
  семейств между выборками, возобновлением и сравнительным испытанием пяти
  замороженных базовых алгоритмов;
- полигональная иерархическая политика PyTorch, совместимое вознаграждение v2,
  возобновляемые BC/PPO и проверяемая оценка нейросетевого и гибридного режимов;
- асинхронная вкладка настольного приложения для `polygon_problem` с ходом
  выполнения, отменой, метриками и сохранением независимо проверенного
  `polygon_solution`;
- изолированный прикладной контур A6: GUI получает только структуры
  представления, а JSON, поиск, точная проверка и рабочий поток находятся в
  инфраструктурных адаптерах;
- модульные тесты доменного и прикладного слоёв.

Текущие ограничения: полигональный графический интерфейс работает в режиме
просмотра без редактора; пока нет рабочего импорта DXF/SVG, вложения деталей в
отверстия и проверенной полигональной контрольной точки модели. Текущий
исполняемый файл нельзя
описывать как готовую промышленную CAD/CAM-систему.

## Сборка

Требования:

- CMake 3.27 или новее;
- компилятор с поддержкой C++20;
- Qt 6 с компонентами `Core` и `Widgets`;
- Git для загрузки закреплённой версии `AIPackaging_Math`.

Отладочная сборка Windows:

```powershell
$qtDir = "C:/Qt/6.9.3/msvc2022_64/lib/cmake/Qt6" # Укажите установленный комплект Qt.
cmake --preset windows-debug -DQt6_DIR="$qtDir"
cmake --build --preset build-windows-debug
```

Сборка и запуск тестов в Windows:

```powershell
$qtDir = "C:/Qt/6.9.3/msvc2022_64/lib/cmake/Qt6" # Укажите установленный комплект Qt.
cmake --preset windows-tests -DQt6_DIR="$qtDir"
cmake --build --preset build-windows-tests
ctest --test-dir build/windows-tests -C Debug --output-on-failure
```

Для Linux и macOS определены аналогичные предустановки CMake. Вместо передачи `Qt6_DIR`
можно скопировать `CMakeUserPresets.example.json` в игнорируемый Git файл
`CMakeUserPresets.json` и указать в нём локальный путь к Qt. При первой
конфигурации может потребоваться сеть для загрузки зависимостей.

Решатель и тесты без Qt и графического интерфейса:

```powershell
cmake --preset windows-headless-tests
cmake --build --preset build-windows-headless-tests
ctest --test-dir build/windows-headless-tests --output-on-failure
```

Пример запуска CLI:

```powershell
build/windows-headless-tests/src/cli/AIPackaging_Cli.exe solve `
  --input examples/grid/problem-small.json `
  --output build/solution.json `
  --solver area-left-bottom
```

Схемы находятся в `schemas/`, а распространяемые примеры — в `examples/grid/`.
Формат сцены настольного приложения `aipackaging.packing_scene` от форматов решателя
не зависит и в M1 не менялся.

Полигональный CLI использует ту же команду и автоматически распознаёт формат:

```powershell
build/windows-headless-tests/src/cli/AIPackaging_Cli.exe solve `
  --input examples/polygon/problem-small.json `
  --output build/polygon-solution.json `
  --solver area-left-bottom
build/windows-headless-tests/src/cli/AIPackaging_Cli.exe validate `
  --problem examples/polygon/problem-small.json `
  --solution build/polygon-solution.json
```

В настольном приложении откройте вкладку «Полигональный раскрой», выберите
`polygon_problem` v1 и базовый алгоритм. Полные и обычные частичные решения
можно сохранить после автоматической повторной проверки; результат отменённого
поиска доступен только для просмотра.

Python-среда и набор данных:

```powershell
python -m pip install -e ".[dev]"
python -m pytest
python -m aipackaging_ml generate-dataset --output artifacts/datasets/grid-v1
python -m aipackaging_ml verify-dataset artifacts/datasets/grid-v1
python -m aipackaging_ml generate-polygon-dataset `
  --output artifacts/datasets/polygon-v2 --workers 4 --resume
python -m aipackaging_ml verify-polygon-dataset artifacts/datasets/polygon-v2
python -m aipackaging_ml benchmark-polygon-baselines `
  --dataset artifacts/datasets/polygon-v2 `
  --output artifacts/benchmarks/polygon-v2-validation.json
```

Клеточный генератор создаёт 768 задач. Полигональный набор данных версии 2
содержит 384 задачи: 256/64/64,
поровну между `small` и `medium`. `--smoke` создаёт 12 коротких задач — по две
масштабные вариации для каждой выборки и каждого профиля сложности. Число
рабочих процессов и история запусков с `--resume` не меняют опубликованные
байты.

Канонический полигональный набор данных версии 2 заморожен на ревизии кода
`1baf53a8c1f0`. SHA-256 манифеста:
`747ADE28A858DE2F1D484CDF6C942DF07CB59AF017EEB886F8C18D9105422C44`.
Фактические размеры, покрытие и результаты сравнительного испытания приведены в
[отчёте M6.1](docs/experiments/m6-1-polygon-dataset-v2-2026-09-13.md).

CUDA-обучение M3 можно выполнять в WSL2 или непосредственно в проверенной
Windows-среде. Подготовка и команды запуска описаны в
[руководстве M3](docs/m3-training.md). Базовый пакет не зависит от PyTorch;
зависимости обучения устанавливаются через
`python -m pip install -e ".[dev,train]"`.

Полигональное обучение M6.2 выполняется отдельными командами и не подключает
модель к GUI. Команды пробного и канонического запуска приведены в
[руководстве M6.2](docs/m6-2-training.md). Канонический эксперимент прошёл
критерий качества; хеши и результаты приведены в
[отчёте M6.2](docs/experiments/m6-2-polygon-policy-2026-09-16.md).

M6.3 экспортирует выбранную полигональную контрольную точку в два графа ONNX и
добавляет получение вывода на CPU без Python. Комплект можно проверить командой
`validate-model`, использовать в CLI режимами `neural-greedy`,
`neural-best-of`, `hybrid` или выбрать в полигональной вкладке. Порядок поставки
описан в [руководстве M6.3](docs/m6-3-model-delivery.md).

## Структура репозитория

```text
src/core/domain/     Клеточная доменная модель и геометрия
src/core/app/        Сценарии, команды, валидация и стратегии упаковки
src/core/contract/   Общие события и интерфейсы
src/gui/             Пользовательский интерфейс Qt
src/solver/          Клеточная и полигональная среды, поиск и работа с JSON
src/cli/             Интерфейс командной строки исследовательского решателя
src/python/          Низкоуровневые привязки pybind11
python/aipackaging_ml/ API Python, конвейеры наборов данных, обучение и ONNX
tests/               Автоматические тесты C++
examples/            Примеры клеточных фигур
schemas/             Схемы JSON публичных форматов
docs/                Цели, архитектура, качество и план разработки
```

## Правила разработки

- Перед изменениями прочитайте [`AGENTS.md`](AGENTS.md).
- Применяйте `.clang-format` только к изменяемым файлам; не форматируйте весь
  репозиторий вместе с функциональной задачей.
- Используйте `.clang-tidy` как постепенный контроль качества.
- Изменения геометрии, размещения, сериализации и целевой функции должны
  сопровождаться тестами и обновлением документации.

Навигация по документации и известным проблемам находится в
[`docs/README.md`](docs/README.md).
