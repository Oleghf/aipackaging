# AIPackaging

AIPackaging — исследовательская система двумерного раскроя деталей произвольной
формы на прямоугольном листе. Версия `0.11.0` предоставляет рабочее место
технолога, полигональное геометрическое ядро, пять базовых алгоритмов,
нейросетевую политику ONNX и гибридный режим. Каждый опубликованный результат
повторно проверяется точным геометрическим валидатором.

## Что уже работает

- загрузка строгих задач `aipackaging.polygon_problem` версии 1;
- отрезки, круговые дуги, кубические кривые Bézier, вогнутые контуры и отверстия;
- отступ от края листа, междетальный зазор и повороты 0°, 90°, 180° и 270°;
- режимы «Быстрый», «Качественный», «Нейросетевой» и «Рекомендуемый гибридный»;
- отмена поиска, отображение частичного результата и сохранение только после
  независимой проверки;
- строгие черновики `.aipdraft.json`, автоматическое сохранение и восстановление
  незавершённого документа;
- внешний проверяемый комплект ONNX, не требующий Python при работе приложения;
- CLI, привязка Python/C++, обучаемые среды и воспроизводимые исследовательские
  наборы данных.

Сейчас приложение открывает готовую полигональную задачу или черновик,
выполняет раскрой только для полностью проверенного документа и отдельно
сохраняет документ либо решение. Создание задачи и импорт DXF входят в M7.2,
а изменение контуров — в M8. Подробный сценарий описан в
[руководстве пользователя](docs/user-guide.md).

## Быстрый запуск настольного приложения

Требования для Windows:

- CMake 3.27 или новее;
- компилятор с поддержкой C++20;
- Qt 6.9.3 с компонентами `Core` и `Widgets`;
- Git для получения закреплённой версии Clipper2.

```powershell
$qtDir = "C:/Qt/6.9.3/msvc2022_64/lib/cmake/Qt6"
cmake --preset windows-debug -DQt6_DIR="$qtDir"
cmake --build --preset build-windows-debug
```

Предустановка `windows-debug` включает получение вывода ONNX. Если
`AIPACKAGING_ONNXRUNTIME_ROOT` не задан, CMake загружает закреплённый официальный
пакет ONNX Runtime 1.29.0 для Windows x64. Три примера задач копируются рядом с
исполняемым файлом и доступны на начальной странице.

Комплект обученной модели не хранится в Git. Выберите его каталог командой
«Загрузить модель». Формат комплекта и его проверка описаны в
[руководстве по поставке модели](docs/m6-3-model-delivery.md). Без модели
остаются доступны быстрый и качественный режимы.

## Интерфейс командной строки

Сборка без Qt:

```powershell
cmake --preset windows-headless-tests
cmake --build --preset build-windows-headless-tests
```

Полигональный раскрой и проверка результата:

```powershell
build/windows-headless-tests/src/cli/AIPackaging_Cli.exe solve `
  --input examples/polygon/problem-small.json `
  --output build/polygon-solution.json `
  --solver area-left-bottom

build/windows-headless-tests/src/cli/AIPackaging_Cli.exe validate `
  --problem examples/polygon/problem-small.json `
  --solution build/polygon-solution.json
```

Нейросетевые режимы `neural-greedy`, `neural-best-of` и `hybrid` требуют
сборки с `BUILD_ONNX_BACKEND=ON` и параметра `--model <каталог>`.

Клеточные форматы `grid_problem` и `grid_solution` сохраняются в CLI и Python
для воспроизводимости исследований M1–M3. Унаследованные настольные сцены
`aipackaging.packing_scene` и пулы `OBJECT` больше не поддерживаются.

## Python и исследования

Базовый пакет поддерживает Python 3.12–3.13 и не требует PyTorch:

```powershell
python -m pip install -e ".[dev]"
python -m pytest
```

Зависимости обучения устанавливаются отдельно:

```powershell
python -m pip install -e ".[dev,train]"
```

Воспроизведение полигонального обучения и экспорт ONNX описаны в
[руководстве M6.2](docs/m6-2-training.md) и
[руководстве M6.3](docs/m6-3-model-delivery.md). Канонические данные, веса и
результаты запусков находятся вне Git в `artifacts/`.

## Проверки

Стандартные команды:

```powershell
python tools/run_checks.py documentation
python tools/run_checks.py language
python tools/run_checks.py architecture
python tools/run_checks.py nesting
python tools/run_checks.py headless
python tools/run_checks.py desktop --qt-dir "$qtDir"
```

Команда `all` последовательно запускает весь локальный набор проверок. Она не
устанавливает зависимости и не очищает каталоги сборки.

## Структура репозитория

```text
src/nesting/          Общие контракты раскроя
src/solver/           Клеточное и полигональное ядра, поиск, JSON и обучение
src/editor/           Независимая редактируемая модель и локальная проверка
src/persistence/      Строгое чтение и атомарная запись черновиков
src/core/app/         Независимые от Qt прикладные сценарии
src/infrastructure/   Файлы, фоновые работы и внутренние реализации
src/inference/        Получение вывода ONNX
src/gui/              Пользовательский интерфейс Qt Widgets
src/cli/              Интерфейс командной строки
src/python/           Низкоуровневая привязка Python/C++
python/               Пакет обучения и обработки наборов данных
schemas/              Схемы JSON публичных форматов
examples/             Клеточные и полигональные примеры
docs/                 Руководства, архитектура, ADR и отчёты
```

Начните знакомство с документацией с [`docs/README.md`](docs/README.md).
Правила работы в репозитории находятся в [`AGENTS.md`](AGENTS.md).

## Ограничения

Текущая версия работает с одним прямоугольным листом. Не поддерживаются
произвольные углы, зеркальное отражение, дефекты листа, направление материала,
вложение деталей в отверстия, раскрой с общей линией и построение траектории
реза. Значение `kerf` сохраняется как технологическое поле, но пока не изменяет
геометрию размещения.

Лицензия проекта не выбрана. До появления файла `LICENSE` код нельзя считать
открытым или разрешённым к распространению.
